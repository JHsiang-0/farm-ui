# Farm 前端需求基线

版本：v1.0
依据：`API_HANDOFF.md`、`FRONTEND_TODO.md`
维护分支：`feature/code-rewrite`

## 目标

构建一个与 Farm 后端契约一致的 Vue 前端。前端只调用 `API_HANDOFF.md` 中标记为“现有”的接口；标记为“规划”的接口在后端完成前只保留入口或占位，不得发起请求。

## 角色与权限

### REQ-01 登录

用户输入合法的用户名和密码后，前端调用 `POST /api/v1/auth/login`，保存 token、用户 ID、用户名和角色，并跳转到农场看板。

### REQ-02 认证失效

当接口返回 401 时，前端必须清除持久化登录态，跳转到登录页，并提示用户重新登录；未登录用户不能访问业务路由。

### REQ-03 角色访问

- `ADMIN` 可以访问打印机配置、扫描、批量添加和网格位置维护。
- `OPERATOR` 可以查看设备、操作文件和创建/控制打印任务，但不能访问 ADMIN 专属页面。
- 菜单隐藏不能代替路由守卫，直接输入地址也必须校验角色。

### REQ-04 用户创建边界

登录页不提供公开注册。用户创建属于 ADMIN 用户管理能力，待用户管理页面和对应接口完成后再开放。

## 当前业务范围

前端第一阶段支持：

1. 登录和退出。
2. 个人资料查看、邮箱/手机号更新和密码修改。
3. 打印机分页、看板、配置和当前可用控制。
4. 文件上传、筛选、文件夹、下载和删除。
5. 任务队列、历史、创建、派发、安全确认、安全启动、取消、暂停和急停。
6. WebSocket 设备和任务实时状态。

## 契约要求

- REST API 使用 `/api/v1` 前缀和 Bearer Token。
- 成功响应统一为 `{ code, message, data, timestamp }`；`data=null` 是合法成功结果。
- ID、分页、时间、文件大小和进度遵循 `API_HANDOFF.md` 的格式约定。
- 任务状态只使用 `QUEUED`、`ASSIGNED`、`READY`、`PRINTING`、`PAUSED`、`COMPLETED`、`FAILED`、`CANCELLED`。
- 前端不得读取或展示 `apiKey`、`rustfsKey`、内部存储路径等敏感字段。

## 暂不实现

后端规划接口完成前，前端不调用以下能力：打印机详情 API、打印机历史/统计、恢复、任务重试、重新排队、优先级调整、文件目录树、文件关联任务和安全预览。

## 验收标准

- ADMIN 和 OPERATOR 可以登录，并只能进入自己有权限的路由。
- 登录过期后页面状态和本地持久化数据被清除。
- Mock 与真实接口使用同一 API 模块和数据结构。
- 个人资料只调用当前登录用户的 profile 接口，不能修改角色或其他用户信息。
- 401、403、资源不存在、设备离线、设备忙碌和网络错误有明确提示。
- `npm run lint` 和 `npm run build` 通过，且不提交环境凭据。
